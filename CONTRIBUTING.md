# Contributing to Agentic-Skills

Contributions are welcome when they improve practical usefulness, clarity, portability, evidence discipline or responsible use.

You do not need to build a new skill to contribute. Small, focused improvements are useful.

## Good first contributions

Examples include:

- correct or clarify documentation;
- add a tested usage example;
- report a country-specific edge case;
- improve evidence or data-quality safeguards;
- improve accessibility, safeguarding, privacy or inclusion guidance;
- add an interoperability note for a supported workflow;
- improve a workflow demonstration;
- propose a missing development-sector expert;
- document a non-sensitive organisation or country adaptation.

## Before you open a pull request

Please keep the change focused and explain:

1. what problem the change addresses;
2. who benefits from it;
3. which skill, workflow or document is affected;
4. how you tested or reviewed it;
5. whether it changes evidence, privacy, safeguarding, localisation or human-review expectations.

Do not add fabricated statistics, citations, organisational experience, performance results, adoption claims, ROI claims or time-saving claims.

## Development Sector Experts

Changes to the 29-skill Development Sector Experts suite must also follow its detailed [suite-specific contribution standards](development-sector-experts/CONTRIBUTING.md), including standalone operation, country awareness, evidence discipline, non-fabrication and responsible-use requirements.

## New skills and expert requests

A useful new skill should solve a recurring professional workflow rather than merely imitate a persona.

For a proposed expert or major workflow, describe:

- the users;
- the professional problem;
- expected tasks and outputs;
- country/localisation considerations;
- evidence requirements;
- major failure modes;
- required human oversight;
- relationship to existing skills.

If you are not ready to implement it, open the relevant issue form instead.

## Country and organisation adaptations

Country-specific contributions should improve local accuracy without presenting one country's institutional arrangements as universal.

Organisation-specific examples should be generalised before publication. Do not publish confidential proposals, internal documents, personal data, restricted donor material or proprietary organisational knowledge.

## Pull requests

Use the repository pull-request template. Keep unrelated changes separate where practical.

A strong pull request states:

- what changed;
- why it creates user value;
- how it was validated;
- what limitations remain;
- whether responsible-AI or evidence controls were affected.

## Community standards

Participation is governed by the repository [Code of Conduct](CODE_OF_CONDUCT.md).

For a problem, improvement request, sector-expert request, country adaptation or use-case example, use the repository's issue forms so enough context is available for review.
